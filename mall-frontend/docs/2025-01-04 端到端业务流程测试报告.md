## 发现的问题列表

### 🔴 阻塞性问题

#### 1. 订单列表显示异常
- **严重程度**: 阻塞
- **问题描述**: 订单列表页面显示"暂无数据"，但分页显示"共 1 条记录"
- **复现步骤**:
  1. 访问 http://localhost:3002/orders
  2. 观察表格内容
- **API状态**: 
  - 无参数请求返回 400 错误（缺少 `page` 和 `page_size`）
  - 带参数请求返回 200 OK，数据正确
- **根本原因**: 前端 Redux store 或组件渲染逻辑问题，数据已获取但未正确显示
- **影响范围**: 用户无法查看订单列表
- **建议修复**: 检查 `orderSlice` 的 `fulfilled` reducer 和 Table 组件的 `dataSource` 绑定

### 🟡 严重问题

#### 2. 前后端字段名不一致
- **严重程度**: 严重
- **问题描述**: 多个 API 存在前后端字段名不匹配问题
- **影响的 API**:
  - 登录 API: `email` vs `username`
  - 地址 API: `name/phone/detail` vs `receiver_name/receiver_phone/detail_address`
  - 订单 API: `items/shipping_address` vs `cart_item_ids/扁平化地址字段`
  - 支付 API: 缺少必填字段
- **根本原因**: 前后端接口文档不同步，缺少统一的类型定义
- **建议修复**: 
  1. 建立统一的 API 文档（OpenAPI/Swagger）
  2. 使用代码生成工具自动生成前端类型定义
  3. 添加集成测试覆盖所有 API

#### 3. 支付配置依赖数据库
- **严重程度**: 严重
- **问题描述**: 支付服务严格依赖 `payment_configs` 表，开发环境无配置时无法创建支付
- **修复方案**: 已添加开发模式回退逻辑（Debug=true 时使用内置默认配置）
- **生产风险**: 需确保生产环境正确配置支付方式，否则会导致支付失败
- **建议**: 添加配置检查脚本，部署前验证支付配置完整性

### 🟢 一般问题

#### 4. 前端代码风格问题
- **严重程度**: 一般
- **问题描述**: 大量使用内联样式，违反代码规范
- **影响文件**: `payment/page.tsx`, `checkout/page.tsx` 等
- **建议修复**: 迁移到 CSS Modules 或 styled-components

#### 5. Ant Design 警告
- **严重程度**: 轻微
- **问题描述**: `<Spin tip="..." />` 在非嵌套模式下使用会产生警告
- **建议修复**: 使用 `<Spin><div>...</div></Spin>` 嵌套模式

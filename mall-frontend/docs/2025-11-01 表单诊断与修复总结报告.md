### ⚠️ 问题3：用户名和邮箱实时校验未触发（低优先级）

**诊断状态**：⚠️ **需要进一步检查代码实现**

**测试结果**：
- ✅ 在注册页面输入用户名 `testuser2025`（≥3个字符）
- ✅ 输入邮箱 `testuser2025@example.com`（完整邮箱格式）
- ❌ Network 面板中未发现实时校验 API 调用
  - 未发现：`GET /api/v1/auth/check-username?username=testuser2025`
  - 未发现：`GET /api/v1/auth/check-email?email=testuser2025@example.com`

**代码分析**：

1. **实时校验函数已实现**：
   - `validateUsername(username: string)` - 当用户名长度 ≥3 时触发
   - `validateEmail(email: string)` - 当邮箱格式正确时触发

2. **onChange 事件绑定**：
   ```typescript
   // 用户名输入框
   onChange={e => {
     const value = e.target.value;
     if (value.length >= 3) {
       validateUsername(value);
     } else {
       setValidationStatus(prev => ({ ...prev, username: '' }));
     }
   }}
   
   // 邮箱输入框
   onChange={e => {
     const value = e.target.value;
     if (value && /^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(value)) {
       validateEmail(value);
     } else {
       setValidationStatus(prev => ({ ...prev, email: '' }));
     }
   }}
   ```

3. **可能的原因**：
   - **后端服务未运行**：实时校验 API 调用可能因为网络错误或后端不可用而被静默失败（catch 块中设置了 error 状态但未显示错误）
   - **防抖延迟**：代码中没有看到防抖实现，但可能需要添加以避免频繁调用
   - **错误静默处理**：`validateUsername` 和 `validateEmail` 的 catch 块只设置了 error 状态，没有显示错误消息，可能导致用户无法察觉 API 调用失败

**建议的优化方案**：

1. **添加防抖延迟**（500-800ms）：
   ```typescript
   const debouncedValidateUsername = useMemo(
     () => debounce(validateUsername, 800),
     [validateUsername]
   );
   ```

2. **添加 onBlur 兜底触发**：
   ```typescript
   onBlur={e => {
     const value = e.target.value;
     if (value.length >= 3 && validationStatus.username === '') {
       validateUsername(value);
     }
   }}
   ```

3. **改进错误处理**：在 catch 块中显示友好的错误提示（如"无法验证用户名可用性，请稍后重试"）

**优先级**：低（不影响核心功能，用户体验优化）

### 修复2：服务端错误提示规范化

**文件**：
- `mall-frontend/src/app/login/page.tsx` - Alert 组件的 error 显示
- `mall-frontend/src/app/register/page.tsx` - `result.payload` 错误处理

**修改内容**：

1. **登录页 Alert**：
   ```typescript
   // 修改前
   description={error}
   
   // 修改后
   description={typeof error === 'string' ? error : JSON.stringify(error)}
   ```

2. **注册页错误处理**：
   ```typescript
   // 修改前
   message.error((result.payload as string) || '注册失败，请稍后重试');
   
   // 修改后
   const errorMsg = typeof result.payload === 'string' 
     ? result.payload 
     : (result.payload as any)?.message || (result.payload as any)?.error || JSON.stringify(result.payload);
   message.error(errorMsg || '注册失败，请稍后重试');
   ```

**效果**：
- ✅ 即使后端返回对象类型的错误，也会正确转换为字符串显示
- ✅ 优先显示 `message` 或 `error` 字段，如果没有则显示 JSON 字符串

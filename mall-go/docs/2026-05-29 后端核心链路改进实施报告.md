## 一、背景

两份 AI 分析文档分别从「注册/登录」与「加购/下单」两条核心链路提出改进建议。实施前已逐条对照源码验证现状，区分出「AI 担心但已实现」与「AI 担心且确实缺失」两类，仅对**真实缺口**动手，避免重复造轮子。

**审计结论**：项目骨架已达中高级水准（库存回滚补偿 `rollbackStock`、Redis 锁 Lua 安全释放、OrderItem 快照字段、RefreshToken、Casbin RBAC、登录日志、购物车合并、10 态订单状态机均已存在），本次仅补 7 个 P0/P1/P2 缺口。

## 二、已实施的 7 项改进

### 🔴 P0-1 订单创建幂等键（防双倍订单）

| 项 | 内容 |
|---|---|
| 问题 | `CreateOrder` 仅用 `AcquireOrderLock` 防抖，锁在 `defer` 时立即释放；网络抖动重试会创建第二个相同订单 |
| 改动 | Order 新增 `IdempotencyKey *string`（唯一索引）；handler 优先读 `Idempotency-Key` Header；service 入口先按 key 查历史订单命中即返回，并发撞唯一索引时重查返回旧单 |
| 文件 | `internal/model/order.go`、`internal/handler/order/order.go`、`pkg/order/order_service.go` |
| 关键设计 | 字段用 **`*string`** 而非 `string`：空值落库为 NULL，规避 MySQL 唯一索引「允许多 NULL、不允许多空串」导致的存量数据迁移失败 |

### 🔴 P0-2 下单删购物车归属校验（防越权）

| 项 | 内容 |
|---|---|
| 问题 | 清理购物车 `Where("id IN ?", CartItemIDs)` 缺 `cart_id` 约束，语义不严谨 |
| 改动 | 删除加 `AND cart_id = ?` 约束；并在查询后断言 `len(cartItems) == len(CartItemIDs)`，掺杂越权 ID 直接报错而非静默丢弃 |
| 文件 | `pkg/order/order_service.go` |

### 🟡 P1-3 注册捕获 DB 唯一冲突

| 项 | 内容 |
|---|---|
| 问题 | 并发注册下两请求同时通过 SELECT 检查后双双 INSERT，第二个撞唯一索引仅返回泛化「创建用户失败」 |
| 改动 | `Create` 后 `errors.Is(err, gorm.ErrDuplicatedKey)` → 返回「用户名、邮箱或手机号已被注册」 |
| 文件 | `pkg/user/register_service.go` |

### 🟡 P1-4 自动关单定时器（释放被占库存）

| 项 | 内容 |
|---|---|
| 问题 | `StatusService.AutoUpdateExpiredOrders()`（扫超时 pending 单→取消+恢复库存、超时 delivered 单→自动确认收货）**已实现，但无定时器周期调用** |
| 改动 | 新建 `pkg/order/scheduler.go`：`time.Ticker` 每分钟调用现成方法（复用，DRY）；启动即跑一次；`main.go` 装配 |
| 文件 | `pkg/order/scheduler.go`（新建）、`cmd/server/main.go` |

### 🟡 P1-5 登录锁定返回 retry_after

| 项 | 内容 |
|---|---|
| 问题 | 锁定时仅回错误文案「账户已被锁定」，前端无法做倒计时 UX |
| 改动 | 新增 `buildLockInfo` 计算 `locked_until` + `retry_after`（秒）；锁定分支与「密码错误触发锁定」分支均用 `response.JSON` 带 data 返回 401 |
| 文件 | `internal/handler/user/user.go` |
| 说明 | 改的是**实际生效的 `handler.Login`**（路由 `/login` 绑定它），而非未接线的 `LoginService.Login` |

### 🟡 P1-6 敏感操作审计日志

| 项 | 内容 |
|---|---|
| 问题 | 仅有登录日志 `UserLoginLog`，密码/邮箱变更无审计 |
| 改动 | 新建 `AuditLog` 模型 + `pkg/audit` 服务（全局单例，写入失败不阻断主流程）；接入 `ProfileService.ChangePassword/ChangeEmail`（真正改数据的逻辑）+ `handler.ResetPassword`；AutoMigrate 注册建表 |
| 文件 | `internal/model/audit_log.go`（新建）、`pkg/audit/audit_service.go`（新建）、`pkg/user/profile_service.go`、`internal/handler/user/user.go`、`pkg/database/database.go`、`cmd/server/main.go` |
| 说明 | 角色变更 `AssignRole` 已有专门的 `RoleChangeLog`，不重复；密码类只记「已变更」事实，绝不记明文 |

### 🟢 P2-7 JWT SessionID/DeviceID + 踢人/登出闭环

| 项 | 内容 |
|---|---|
| 问题 | JWT Claims 无 SessionID/DeviceID；`JWTBlacklistMiddleware` 与 `Logout` handler **均已建好但从未接线**（黑名单中间件未挂载、Logout 是桩） |
| 改动 | ① Claims 加 `SessionID`/`DeviceID` + 新增 `GenerateTokenWithSession`（旧函数委托新函数，DRY，向后兼容）；② 登录用 `crypto/rand` 生成 SessionID、写入 DeviceID；③ 生效的 `AuthMiddleware` 接通黑名单检查（用全局单例，**零装配链注入**）；④ `Logout` 真正把令牌写入黑名单 + 审计 |
| 文件 | `pkg/auth/jwt.go`、`internal/handler/middleware/middleware.go`、`internal/handler/user/user.go` |
| 价值 | 复用现有 `security.JWTBlacklist`（rdb=nil 时优雅降级），实现「登出/踢人后令牌立即失效」的安全闭环 |

## 三、数据库迁移说明

无需手写迁移脚本——`pkg/database/database.go` 的 `AutoMigrate` 会自动：
1. 给 `orders` 表加 `idempotency_key` 列（`*string` → 可空，唯一索引 `uk_idempotency_key`，存量行为 NULL 不冲突）；
2. 创建 `audit_logs` 表。

## 四、本期未做（明确降级，附理由）

| 项 | 理由 |
|---|---|
| P1-5 登录失败计数迁移 Redis | 当前 DB 字段方案（`LoginAttempts`/`LockedUntil`）功能完整正确，Redis 化属纯性能优化；强行给 `LoginService` 注入 rdb 会污染整条 `handler→routes` 装配链，违反 KISS，收益/风险不匹配 → 降 P3 |
| P2-7 SessionID↔Redis 映射做「单设备互斥登录」 | 黑名单机制已闭环「登出/踢人/令牌失效」核心安全诉求；按 SessionID 主动失效特定会话需登录流程注入 rdb，属细粒度增强。Claims 字段已就位，未来接入只需填充 → 降 P3 |
| 冻结库存模型 / 缓存删除补偿队列 / getOrCreateCart 并发锁 | `rollbackStock` 补偿已闭环；缓存删除失败属性能体验问题；Cart `user_id` 已有唯一索引兜底 → 维持原计划 P3 |

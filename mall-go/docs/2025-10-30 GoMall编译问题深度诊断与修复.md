# GoMall 编译问题深度诊断与修复（2025-10-30）

## 结论摘要
- 根因：仓库根目录存在 go.mod（module=gomall），而业务代码位于 mall-go 子目录且该目录内也存在 go.mod（module=mall-go）。根模块与子模块并存导致 import 解析以根模块为准，`gomall/internal/...` 被当作标准库（GOROOT/src）路径解析，引发 `package gomall/internal/config is not in std`。
- 解决方案：删除根目录 go.mod/go.sum/go.work，仅保留 mall-go 目录为唯一 Go Module；在 mall-go 下执行 go mod tidy & go build。
- 验证结果：`mall-go/bin/server.exe` 构建成功（55,495,680 bytes）。

## 现象与错误日志
- 典型错误：
```
package gomall/internal/config is not in std (C:\Program Files\Go\src\gomall\internal\config)
```
- go env / list 关键输出：
```
# 修复前（在仓库根目录）
GOMOD = E:\...\goProject\go.mod

# 修复后（在 mall-go 目录）
GOMOD = E:\...\goProject\mall-go\go.mod

go list -m -> mall-go
```

## 根因分析（模块解析）
- Go 的 import 路径以“当前模块根目录”为起点映射到磁盘路径。
- 根目录 go.mod 的 `module gomall` 让编译器认为 `gomall/internal/config` 应位于仓库根下的 `internal/config`，但实际代码在 `mall-go/internal/config`。
- 由于根模块找不到该包，Go 继续尝试 GOROOT（标准库）路径，因此出现 `is not in std`。
- 与 GOPATH 无直接关系（尽管 GOPATH 显示为默认值 C:\Users\Akari\go），关键在于“错误的模块根”。
